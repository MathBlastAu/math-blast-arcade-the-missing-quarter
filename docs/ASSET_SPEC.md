# Math Blast Arcade — art production spec (the contract between art and code)

Game: **Math Blast Arcade — The Missing Quarter**. Premium 2D side-scrolling pixel-art platformer
for children aged 8–11 (Australian Year 4 fractions). Setting: Kepler Station, a fuel station
orbiting a planet. Hero: Jake Nova, Junior Fuel Inspector (orange flight suit, goggles).
Villain: the Fraction Phantom — "a translucent blue hologram made of shifting fraction bars and
number lines, with a calm, precise voice".

The game code loads every asset by the keys, frame sizes and animation names written here, via
manifest fragments. **Follow names and sizes exactly.** If you must deviate, record it in your
manifest fragment AND state it in your final report.

## How the art is made

- All art is generated by Python scripts in `/home/claude/mathblast-arcade/art/` using Pillow and
  the shared toolkit `art/pix.py` (palette `RAMPS`/`C`, `ascii_sprite`, `outline`, `capsule`,
  `disc`, `dither_pick`, `sheet`, `save`, `preview`, `manifest`). Read `pix.py` first.
- Style anchors already finished — LOOK AT THEM before drawing anything:
  - `art/_preview/jake_big.png`, `art/_preview/jake.png` (hero, made by `art/jake.py`)
  - `art/_preview/mock_dock.png`, `mock_reactor.png`, `mock_zerog.png` (tiles, `art/tiles.py`)
- Do **not** edit `pix.py`, `jake.py`, `tiles.py`. Put new helpers in your own script(s).
  You may `import jake` to reuse its rig.
- Output PNGs go under `/home/claude/mathblast-arcade/assets/` with `pix.save(img, "sub/name.png")`.
- Write one manifest fragment with `pix.manifest("<your part>", {...})`:

```json
{ "sheets": { "<key>": { "file": "sprites/x.png", "fw": 32, "fh": 32,
                         "anims": { "<anim>": {"frames": [0,1,2], "fps": 10, "loop": true} },
                         "names": { "<frameName>": 0 } } },
  "images": { "<key>": { "file": "bg/x.png" } },
  "fonts":  { "<key>": { "png": "fonts/x.png", "fnt": "fonts/x.fnt" } } }
```
  Sheets are uniform grids, frames numbered left-to-right, top-to-bottom. `anims` and `names`
  are optional per sheet. The animation key the game uses is `<sheetKey>_<anim>`.
- Your script must be re-runnable: `python3 art/<yourscript>.py` regenerates everything you own.

## Style guide

- Modern 16-bit pixel art: SNES/GBA-era pixel density with contemporary colour and lighting.
  In game, 1 art pixel = 2 screen pixels (960×540 canvas, 480×270 visible world), nearest-neighbour.
- Colours come from `pix.RAMPS` (hue-shifted ramps, dark→light). No pure black; darkest is ink0.
  Tile skins in `tiles.py` define the hull colours per area — match them for area-specific art.
- Light comes from the top-left. Highlights top/left, core shadow bottom/right. 3–5 tones per material.
- **Gameplay objects and characters**: 1px `ink0` outer outline, strong value contrast, one bright
  accent. Colour language: cyan = friendly energy/interactive; orange & gold = Jake and collectibles;
  pink/purple = Phantom, glitch and enemies; red = hazard; green = success.
- **Backgrounds**: no dark outlines, lower contrast and saturation than gameplay, values kept in the
  dark-to-mid range so the hero (orange) and platforms (steel with bright top edge) always read on top.
  Use ordered dithering (`dither_pick`) for large gradients. Big readable shapes first, detail second.
- No blurry anti-aliasing, no soft gradients on sprites. Semi-transparent pixels only for holograms,
  glows, FX and smoke.
- Animation: loops ≥ 4 frames; use squash-and-stretch, anticipation, secondary motion. Nothing may
  jitter unintentionally (anchor points stay put between frames).
- Characters are anchored bottom-centre of their frame (feet on the bottom rows, 1px outline row
  allowed). Floating things are centred in their frame.
- Blank "display" areas noted below must be left as flat dark screens (`navy0`/`ink1`) — the game
  draws fraction labels on them at run time.

## Quality bar and process (required)

Previous attempts at this game were rejected for using basic shapes. This must look like a
commercial indie game. For every asset: render → `pix.preview()` → **open the preview PNG and
look at it** → critique honestly (silhouette, readability at 1×/2×, shading, appeal, consistency
with Jake and the tiles) → fix → repeat. Minimum three look-and-fix passes on every major asset;
keep going while you can still see something a professional pixel artist would fix. Compose key
assets over the real tiles/backgrounds (see `tiles.mock_room`) to judge them in context.
Final report: list the files produced, the manifest keys, any deviations, and an honest note of
anything you think is still weak.

Design notes
- **Fraction Phantom** (the star villain, ~70 px tall inside the 96 frame, body centred at 48,48, faces
  the viewer with a slight lean; the game flips it). A hooded spectral hologram: translucent
  cyan/blue body literally built from stacked horizontal *fraction bars* (bars split into 2, 3, 4,
  8 segments, some segments lit, some hollow) that slide and re-divide between frames, with
  number-line tick marks running down the cloak edge. No legs — the body tapers into loose
  floating bar segments. Inside the hood: darkness and two bright calm eyes. On the chest an
  emblem: **a circle with one quarter wedge missing**. Two detached floating hands. Use alpha
  140–235 on body pixels and occasional empty scanlines for the hologram feel; pink/purple glitch
  pixels as accents. `attack`: raises a hand, bars flare. `stunned`: slumped, dim, eyes as spirals/X,
  emblem cracked. `defeat`: violent glitch, splits into separate bars that drift apart and fade.
  It must read as menacing but not frightening for an 8-year-old: elegant, mysterious, a bit smug.
- **Crawler** "scrambled maintenance bot": chunky dome robot on stubby legs or treads, one big
  glitching pink eye, bent antenna. Faces right. Feet on the bottom rows. `squash`: flattened, then sparks.
- **Drone** "glitch drone": hovering sphere/saucer with a thruster ring, pink eye, small fins.
  Centred in frame. The game adds the bobbing motion — animate rotor/thruster/eye only.
- **Priya**, Fuel Officer: same doll proportions as Jake (you can adapt `jake.py`'s rig). Teal
  station uniform (cyan ramp) with navy trousers, dark hair tied back, brown skin (skin ramp 1–3),
  clipboard or tablet optional. Stern-but-kind. Faces LEFT (she greets Jake arriving from the left) —
  i.e. draw facing right like Jake and flip the sheet, or draw facing left; just make sure the saved
  sheet faces left.
- **Portraits** 48×48 busts for the dialogue box, more detailed than the sprites but clearly the
  same characters (Jake: brown tousled hair, cyan goggles pushed up on forehead, orange suit, white
  collar). Transparent background. Expressions must be clearly different at a glance.
